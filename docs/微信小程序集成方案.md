# 微信小程序局域网集成方案

本文说明如何让一个**已发布的**微信小程序在局域网内与家庭影院系统通信、播放视频。
小程序端代码已直接集成到独立的微信小程序工程（工具箱）：`pages/family`、`pages/family-player`、`utils/fv/{discovery,tcp,api}.js`，本仓仅保留服务端通信层。

## 1. 核心约束

微信小程序发布版对网络访问有硬性限制：

| API | 发布版限制 | 局域网可用性 |
|-----|-----------|-------------|
| `wx.request` / `wx.connectSocket` | 必须「已备案 HTTPS 域名」 | ❌ 不能用局域网 IP |
| `<video>` / `<image>` 网络资源 | 同上（视频/downloadFile 合法域名） | ❌ 不能用局域网 IP |
| `wx.createUDPSocket` / `wx.createTCPSocket` | 无域名校验（为局域网设备通信设计） | ✅ 可用 |

因此采用**双通道**架构。

## 2. 架构总览

```
微信小程序                              家庭影院服务器（局域网）
┌───────────────────────┐             ┌──────────────────────────────┐
│ utils/discovery.js     │──UDP广播──▶ │ lan.ts  UDP :9527 服务发现     │
│ (wx.createUDPSocket)   │◀──回复───── │   返回 {tcpPort, publicBaseUrl}│
├───────────────────────┤             ├──────────────────────────────┤
│ utils/tcp.js           │──TCP──────▶ │ lan.ts  TCP :9528 JSON-RPC     │
│ (wx.createTCPSocket)   │◀─────────── │   影库/搜索/收藏/进度/字幕/封面 │
├───────────────────────┤             ├──────────────────────────────┤
│ <video src=HTTPS URL>  │──HTTPS────▶ │ Caddy :443 ─反代─▶ Express :8080│
│  仅播放画面走这条       │             │   /api/media/:id/stream (Range) │
└───────────────────────┘             └──────────────────────────────┘
```

- **控制面**（浏览/搜索/分页/收藏/进度/媒体探测/字幕/**封面**）：全走 TCP Socket，免域名、可发布、不出公网。
- **视频画面**：`<video>` 只能吃 HTTPS 备案域名，需一台反代（示例用 Caddy）指向 Express。
- **封面图**特例：以 base64 经 TCP 回传，转成 `data:image/...` 供 `<image>` 显示，**无需域名**。

## 3. 后端接口（lan.ts）

### UDP 发现（默认 9527）
收到任意数据报即回复：

```json
{ "service": "family-video", "tcpPort": 9528, "udpPort": 9527,
  "publicBaseUrl": "https://tv.example.com", "lanUrls": ["http://192.168.31.170:8080"] }
```

### TCP JSON-RPC（默认 9528）
换行(`\n`)分帧。请求 `{"id":1,"method":"...","params":{...}}` → 响应 `{"id":1,"ok":true,"result":...}` 或 `{"id":1,"ok":false,"error":"..."}`。

| method | params | result |
|--------|--------|--------|
| `server.info` | — | 服务信息（含 lanUrls、publicBaseUrl） |
| `library.list` | `keyword?, category?, page?, pageSize?` | `{total, page, pageSize, movies[]}` |
| `library.refresh` | — | `{total, scannedAt}` |
| `movie.get` | `id` | 影片对象（不含服务器路径） |
| `favorites.list` | `deviceId` | `movieId[]` |
| `favorites.toggle` | `deviceId, movieId` | `{favorite}` |
| `favorites.batch` | `deviceId, movieIds[], favorite` | `{ok}` |
| `progress.list` | `deviceId` | `Progress[]` |
| `progress.set` | `deviceId, movieId, position, duration` | `{ok}` |
| `progress.remove` | `deviceId, movieId` | `{ok}` |
| `media.probe` | `id` | `{durationSec, audioCodec, videoCodec}` |
| `media.subtitle` | `id, track?` | `{vtt}` |
| `media.thumbnail` | `id` | `{base64, mime}` |

> `movies` 已剥离 `path`/`root` 字段，不泄露服务器文件系统结构。

## 4. 配置项

`.data/config.json`（或环境变量）：

| 字段 | 环境变量 | 默认 | 说明 |
|------|---------|------|------|
| `lan.udpPort` | `FV_LAN_UDP_PORT` | 9527 | UDP 发现端口 |
| `lan.tcpPort` | `FV_LAN_TCP_PORT` | 9528 | TCP 通信端口 |
| `publicBaseUrl` | `FV_PUBLIC_BASE_URL` | 空 | 视频播放用的 HTTPS 备案域名；留空则小程序仅可浏览、不可播放 |

## 5. 部署步骤

### 5.1 端口放行
`docker-compose up` 已映射 `9527/udp`、`9528/tcp`。局域网防火墙需放行入站：
- **WSL2 mirrored 模式**：Docker 容器服务需手动在 Windows 防火墙放行入站规则（见项目运维约定）。
- 独立 Linux 主机：`ufw allow 9527/udp && ufw allow 9528/tcp`。

### 5.2 视频播放：方案1（备案域名 + DNS-01 证书 + 本地 DNS 指内网）

目标：手机在**家里 WiFi** 下用 `https://<你的域名>` 播放，实际流量走**局域网**，不出公网、
不需要把 80/443 暴露到公网（绕开家宽封端口/无公网 IP 的问题）。前提：域名**已 ICP 备案**。

**步骤**

1. **准备证书**（DNS-01，纯 API）。把域名 DNS 托管到支持 API 的服务商（如 Cloudflare），然后：
   ```bash
   export CF_API_TOKEN='你的令牌'                 # Cloudflare 示例；其他商见 issue-cert.sh 头部说明
   make cert-issue FV_DOMAIN=tv.example.com       # 产物：deploy/caddy/certs/{fullchain,privkey}.pem
   ```
   > 需先安装 `acme.sh`。证书自动续期由 acme.sh 定时任务负责，续期后回调 `docker restart fv-caddy`。

2. **重启家庭影院带 publicBaseUrl，并起 Caddy**（同网络 `fv-net`，Caddy 反代 `family-video:8080`）：
   ```bash
   make docker-up MEDIA_DIR=/mnt/d/迅雷下载 FV_DOMAIN=tv.example.com
   make caddy-up  FV_DOMAIN=tv.example.com
   ```
   `make docker-up` 会自动把 `FV_PUBLIC_BASE_URL=https://tv.example.com` 下发给服务端。

3. **本地 DNS 把域名指到内网 IP**：在家里路由器/Dnsmasq/Pi-hole 加一条
   `tv.example.com → 192.168.31.170`（本机局域网 IP）。手机连家里 WiFi 即可命中内网。
   注意：这只是**解析**指内网；备案与公共证书校验仍成立，微信客户端不关心域名解析到哪。

4. **放行防火墙 443**（WSL2 mirrored）：手机到 Caddy 的 443 入站需允许：
   ```powershell
   New-NetFirewallRule -DisplayName "FV HTTPS 443" -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow -Profile Any
   ```

5. **微信公众平台后台** → 开发管理 → 服务器域名 → 将 `https://tv.example.com` 加入
   `downloadFile 合法域名`/`video` 相关白名单（`<video>` 依赖）。控制面走 TCP，**无需**配 request 域名。

**验证**：同网段设备 `curl -k https://<域名>/api/health` 应返回健康 JSON；小程序影库页顶部不再提示
「未配置 HTTPS 播放域名」，点影片即可进播放器经局域网 HTTPS 出流。

> **不想搞域名/证书**的替代：以**体验版**分发 + 家人开「不校验合法域名」调试模式，则 `<video>`
> 可直接播 `http://192.168.31.170:8080`（仅适合自家人、不能正式发布）。**发布版**必须走上面的备案域名。

## 6. 验证

无需手机即可跑通后端通信层（先启动服务，再执行）：

```bash
node scripts/lan-test.mjs            # 本机
node scripts/lan-test.mjs 192.168.31.170   # 跨机指定服务器 IP
```

脚本会依次验证 UDP 发现、`server.info`、`library.list`、`media.probe`、`media.thumbnail`、收藏读写，
并断言影片对象不含 `path`/`root`。

小程序端代码已集成到独立的微信小程序工程（工具箱，见 `pages/family`、`pages/family-player`、`utils/fv/`），
真机测试（TCP/UDP 在模拟器无法完全验证），基础库需 ≥ 2.18.0。

## 7. 常见问题

- **发现不到服务器**：确认手机与服务器同网段、UDP 9527 未被防火墙拦截；可在小程序里手动传
  `init({ address, tcpPort })` 跳过广播。
- **能浏览不能播放**：`publicBaseUrl` 未配置，或域名未在小程序后台加入白名单，或路由器不支持
  NAT 环回导致家里设备解析不到内网 IP。
- **AC3/DTS 音轨无声**：播放器页面已按 `media.probe` 结果自动切换 `transcode=1` 音频兼容模式
  （视频不转码，仅音轨转 AAC）。
